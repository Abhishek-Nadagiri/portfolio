# Portfolio Content Requirements Document

## 1. Document Overview

### 1.1 Purpose

This document defines the complete content structure and content requirements for a premium personal portfolio website.

The portfolio must present the individual through three primary identities:

1. Software Engineer
2. Prompt Engineer
3. Content Creator

The portfolio should demonstrate that these three areas are not separate skills, but connected parts of how the individual builds, experiments, and creates digital experiences.

The content must feel personal, authentic, concise, professional, and memorable.

---

# 2. Core Portfolio Identity

The portfolio should communicate:

> Software Engineering + Prompt Engineering + Content Creation

The portfolio should not present the individual as someone who merely lists skills.

Instead, visitors should understand that the individual:

* Builds software
* Experiments with AI and prompting
* Creates and publishes content
* Combines technology and creativity
* Turns ideas into working digital experiences
* Experiments, learns, builds, and publishes

The three identities should remain consistent throughout the entire website.

---

# 3. Content Philosophy

The portfolio should follow these principles:

### 3.1 Show, Don't Just Tell

Whenever possible, prove capabilities through:

* Projects
* GitHub activity
* Prompt experiments
* Content performance
* Experience
* Certifications
* Achievements
* Real measurable results

### 3.2 Use Real Numbers

Use genuine numbers wherever they exist.

Examples:

* Number of projects
* GitHub repositories
* GitHub activity
* LinkedIn reactions
* LinkedIn comments
* LinkedIn impressions/views
* Project users
* Performance improvements
* Internship duration
* Other measurable results

Never invent statistics.

### 3.3 Keep Content Selective

The portfolio should not attempt to include everything about the individual.

Every section should have a clear purpose.

Avoid unnecessary information simply to make the portfolio appear larger.

### 3.4 Authenticity

The content should feel written specifically for the individual.

Avoid:

* Generic AI-generated descriptions
* Generic motivational statements
* Empty corporate language
* Exaggerated claims
* Fake achievements
* Artificial skill ratings

---

# 4. Hero Section

## Purpose

The hero should immediately establish the individual's identity without overwhelming the visitor.

The hero should use a short creative statement rather than simply displaying conventional job titles.

The three identities should appear elsewhere in the portfolio.

## Required Content

The hero should contain:

* Name
* Short creative identity statement
* Concise introduction
* Primary action leading into the portfolio/work

The hero should quickly communicate that the individual builds, experiments, and creates.

## Avoid

Do not make the hero a long biography.

Do not fill the hero with:

* Large skill lists
* Long paragraphs
* Excessive statistics
* Resume information
* Generic motivational quotes

---

# 5. About Me Section

## Purpose

The About section should tell a short personal story.

It should not read like a traditional resume summary.

## Main Theme

The story should focus on the connection between:

Software Engineering + Prompt Engineering + Content Creation.

The visitor should understand how these three areas come together in the individual's work.

## Content Direction

The story can communicate:

* How the individual became interested in technology
* How software development became part of their journey
* How AI and prompting became another creative/technical tool
* How content creation became a way to share ideas and work
* How these areas now work together

The story should remain concise and engaging.

---

# 6. Projects Section

## Purpose

Projects are one of the most important parts of the portfolio.

They should provide evidence of Software Engineering and creative technical ability.

## Presentation Style

Projects should be presented as story-driven experiences.

Instead of simply showing:

Project → Description → Technologies → Button

the project should unfold naturally as the visitor scrolls.

## Project Information

Each major project should communicate:

### 6.1 What

What is the project?

### 6.2 Why

What problem or need does it address?

### 6.3 Creative Solution

What makes the individual's approach interesting, different, or creative?

### 6.4 Development

Where useful, explain the important technologies and implementation decisions.

### 6.5 Result

Include real measurable results when available.

### 6.6 Links

Where applicable:

* Live Demo
* GitHub Repository
* Other relevant project links

## Project Experience

The project presentation should feel like a short story rather than a technical documentation page.

The visitor should naturally discover:

Idea → Problem → Solution → Build → Result

---

# 7. Software Engineering Identity

Software Engineering should be demonstrated primarily through actual work.

## Evidence

Relevant evidence can include:

* Software projects
* Web applications
* AI applications
* APIs
* Databases
* Development tools
* GitHub repositories
* Coding activity
* Deployment experience

The portfolio should avoid presenting Software Engineering as only a list of programming languages.

Actual projects and GitHub activity should provide the strongest evidence.

---

# 8. Prompt Engineering Identity

Prompt Engineering should be presented as a practical skill rather than a simple keyword.

## Required Concept

Show prompt experimentation through examples.

A suitable content structure is:

Prompt → Experiment → Result

The portfolio may show:

* Original prompt
* Improved prompt
* Generated result
* Brief explanation of the improvement

## Important Restriction

Do NOT include an interactive Prompt Playground.

Visitors should not be required to run AI models or experiment with prompts directly inside the portfolio.

Prompt Engineering should remain an informative showcase rather than a live AI application.

---

# 9. Content Creator Section

## Purpose

The Content Creator identity should be demonstrated through actual published content.

## LinkedIn Content

Show exactly:

**2 LinkedIn posts**

These should be the individual's top-performing/highest-engagement posts.

## Each Featured Post Should Include

* Post visual/content
* Short explanation of what the post was about
* Relevant engagement numbers
* Link to the original LinkedIn post

Where available, engagement information may include:

* Reactions
* Comments
* Views/impressions
* Other meaningful performance metrics

Only genuine numbers should be displayed.

## Presentation

The section should feel like a:

**Creator Wall**

The two posts should appear as featured pieces in a premium gallery rather than a normal social-media feed.

---

# 10. Skills Section

The Skills section should contain three clear groups.

## 10.1 Software Engineering

Examples may include:

* Programming
* Web development
* Frameworks
* Databases
* APIs
* Development tools
* Version control
* Deployment

Only include technologies actually known and used.

## 10.2 Prompt Engineering

Examples may include:

* Prompt design
* Prompt optimization
* Structured prompting
* AI workflows
* AI-assisted development
* Prompt experimentation

Only include genuine capabilities.

## 10.3 Content Creation

Examples may include:

* LinkedIn content
* Technical content
* Visual content
* Writing
* Content strategy
* Social media publishing

The exact skills should reflect actual experience.

## Important Rule

Do not use:

Python — 95%

Prompt Engineering — 90%

Content Creation — 85%

or similar artificial progress bars.

Skills should be represented honestly without fake percentages.

---

# 11. Experience Section

## Presentation

Experience should be presented as a simple timeline.

Each experience entry should contain:

* Role
* Organization
* Start date
* End date
* Short description

The section should be easy to scan.

## Avoid

Do not turn Experience into a large case study.

Do not overload every entry with excessive bullet points.

---

# 12. Education Section

Education should remain small.

## Required Information

Include only:

* Degree
* College/Institution

Education should not occupy significant visual space.

Do not add unnecessary academic details unless they are genuinely important to the portfolio.

---

# 13. Achievements & Certifications

## Structure

Use one simple combined section:

**Achievements & Certifications**

It should contain a clean list of relevant:

* Certifications
* Awards
* Recognitions
* Academic achievements
* Professional achievements

The section should remain informative rather than visually dominant.

---

# 14. GitHub Section

GitHub should receive significant attention because it supports the Software Engineering identity.

## Required Content

Where technically possible, show:

* GitHub profile
* Contribution graph
* Repository activity
* Selected repositories
* Commit activity
* Programming language statistics
* Useful GitHub statistics

## Repository Information

Selected repositories can display:

* Repository name
* Description
* Technologies
* Stars, when meaningful
* Relevant activity
* Repository link
* Live demo, when available

The GitHub area should feel like a genuine development portfolio rather than a simple external link.

---

# 15. Resume

The portfolio must **not contain a Resume section**.

Do not include:

* Resume preview
* Resume download button
* Resume page
* Resume navigation item

The portfolio itself should communicate the individual's professional profile.

---

# 16. Contact Section

The Contact section should remain simple.

## Required Contact Methods

Include:

* Email
* LinkedIn
* GitHub

## Do Not Include

No contact form is required.

The visitor should be able to directly choose a communication platform.

---

# 17. Navigation

The navigation must contain the major portfolio sections.

Expected navigation destinations include:

* Home
* About
* Projects
* Skills
* Experience
* Achievements
* GitHub
* Contact

However, the navigation itself should NOT resemble a conventional website navbar.

## Navigation Concept

The portfolio should use a completely experimental navigation concept.

It should feel like a unique signature feature of the website.

The navigation can break conventional patterns while still remaining usable and understandable.

The goal is:

**Unconventional design without sacrificing usability.**

The navigation should feel integrated into the black/chrome visual identity established by the design requirements.

---

# 18. Statistics & Numbers

The portfolio should use real statistics wherever available.

Numbers should be placed naturally within relevant sections.

Examples:

### GitHub

GitHub repositories, contributions, commits, or other genuine activity.

### Content

LinkedIn engagement numbers.

### Projects

Users, performance improvements, dataset sizes, features, or other genuine measurements.

### Experience

Internship duration or other meaningful measurable information.

Do not create a separate statistics section unless the information naturally benefits from one.

---

# 19. Footer

The footer should end the experience with a personal closing message.

## Required Content

A short memorable statement that represents the individual's approach to:

* Building
* Experimenting
* Creating

The footer can also contain essential links, but the main focus should be the personal closing statement.

The footer should feel like the final sentence of the portfolio's story.

---

# 20. Sections That Must NOT Be Included

The portfolio should deliberately avoid unnecessary sections.

Do not include:

* Resume section
* Resume download
* Resume preview
* Now/currently section
* Testimonials
* Recommendations
* Generic quote section
* Generic motivational section
* Fake skill percentages
* Unnecessary personal information
* Prompt Playground
* Unnecessary statistics section
* Excessive generic skill lists

---

# 21. Content Quality Rules

Every piece of content should satisfy at least one of these purposes:

1. Demonstrate a capability
2. Explain a project
3. Show real experience
4. Demonstrate creativity
5. Provide evidence
6. Help visitors understand the individual
7. Make the portfolio memorable

If content does none of these, it should probably be removed.

---

# 22. Tone of Voice

The writing should be:

* Professional
* Confident
* Intelligent
* Clear
* Concise
* Modern
* Personal
* Slightly futuristic
* Technically credible
* Creative without becoming childish

Avoid:

* Overly corporate language
* Generic motivational language
* Excessive buzzwords
* Fake confidence
* Exaggeration
* Long paragraphs
* Generic AI-written phrases

The personality should feel:

**Calm + capable + curious + technical + creative + ambitious**

---

# 23. Relationship Between Content and Design

The content requirements must work together with the previously established visual design system.

The portfolio should combine:

**Content**
Software Engineering + Prompt Engineering + Content Creation

with:

**Visual identity**
Black + Chrome + Luxury + Futuristic + Cinematic + Professional

The content should never become overloaded merely to support visual effects.

Animations should help reveal the story and information rather than distract from it.

---

# 24. Ideal Visitor Journey

The visitor experience should roughly follow:

**Hero**

Understand who the individual is.

↓

**About**

Understand the story and how the three identities connect.

↓

**Projects**

See what the individual actually builds.

↓

**Skills**

Understand the three capability areas.

↓

**Experience**

See professional experience.

↓

**Achievements & Certifications**

See additional proof and recognition.

↓

**GitHub**

Inspect real development activity.

↓

**Content Creator / Creator Wall**

See the two strongest LinkedIn posts and their performance.

↓

**Contact**

Find direct ways to connect.

↓

**Personal Closing Message**

End with a memorable statement.

The exact visual ordering can be adjusted to support the final experimental navigation and cinematic experience.

---

# 25. Core Content Principle

The portfolio should never feel like:

> “Here is everything I have done.”

It should feel like:

> “Here is what I build, how I think, how I experiment, and how I create.”

The portfolio should prove the individual's abilities through real work rather than simply claiming them.

---

# 26. Final Content Direction

The final portfolio should communicate three things above everything else:

### 01 — I Build

Software Engineering is demonstrated through real projects and GitHub activity.

### 02 — I Experiment

Prompt Engineering is demonstrated through practical prompt experiments and AI-related work.

### 03 — I Create

Content Creation is demonstrated through the individual's two strongest LinkedIn posts and their real engagement.

Together, these should create a single professional identity rather than three disconnected portfolios.

## Final Principle

**Build it. Experiment with it. Create with it.**

The portfolio should make those three ideas immediately understandable while keeping the overall experience selective, authentic, technically credible, and memorable.
