# MASTER PROMPT — GENERATE THE TECHNICAL REQUIREMENTS DOCUMENT

You are a senior creative technologist, award-winning interactive web designer, frontend architect, WebGL engineer, motion designer, UX engineer, and performance specialist.

Your task is to create a comprehensive Technical Requirements Document (TRD) for building a highly experimental personal portfolio website.

This must NOT be a generic portfolio website.

The goal is to create a portfolio that feels like a completely new digital experience rather than another template-based developer portfolio.

The website must be:

* Premium
* Royal
* Black/chrome
* Cinematic
* Futuristic
* Technological
* Professional
* Creative
* Memorable
* Highly interactive
* Extremely polished
* Responsive
* Fast
* Accessible
* Technically impressive

The final experience should make visitors think:

"This does not feel like a normal portfolio."

However, the website must never sacrifice usability simply for visual effects.

---

# 1. PRIMARY OBJECTIVE

Build a portfolio that combines:

Software Engineering
+
Prompt Engineering
+
Content Creation

The website should demonstrate these three identities through actual work rather than simply displaying them as labels.

The experience should feel like a combination of:

* Luxury product website
* Experimental digital art
* High-end technology showcase
* Interactive developer portfolio
* Cinematic storytelling experience

Do NOT copy an existing website.

Do NOT use a common portfolio template.

Do NOT create a standard navbar + hero + cards + footer layout.

Invent original interaction patterns and visual arrangements while keeping the interface understandable.

# 36. PERFORMANCE

Target:

* Excellent Core Web Vitals
* Fast first meaningful render
* Optimized images
* Lazy-loaded media
* Code splitting
* Dynamic imports for heavy components
* GPU-conscious animations
* Efficient WebGL
* Minimal main-thread blocking

Avoid:

* Huge JavaScript bundles
* Unoptimized videos
* Excessive shaders
* Unnecessary 3D objects
* Animation loops running when invisible

Use IntersectionObserver or equivalent techniques to pause inactive effects.
